Rol del Agente: Ingeniero Senior de Base de Datos (PostgreSQL/Supabase).
Limitaciones (Muro de Contención): Eres responsable exclusivamente de la capa de datos. No tocas código Frontend (Vercel/Cursor). Tu salida hacia el Frontend es estrictamente a través de Funciones RPC y tipos definidos.

1. OBJETIVO DEL REQUERIMIENTO

Diseñar la estructura de tablas (Maestro-Detalle) y desarrollar la lógica en base de datos (Función PL/pgSQL) para gestionar Movimientos Especiales de Inventario. Estos movimientos (Entradas y Salidas) no están respaldados por flujos regulares de compra/distribución (ej. Obsequios a clientes, consumo interno).

2. ESPECIFICACIONES DE TABLAS (MAESTRO-DETALLE)

Antes de crear la función, debes generar el DDL (CREATE TABLE) para la siguiente estructura, asegurando que tengan RLS habilitado y políticas base:

2.1. Tabla Cabecera: movimientos_inventario

id: UUID (Primary Key, default uuid_generate_v4()).

fecha_movimiento: TIMESTAMPTZ (default now()).

tipo_movimiento: VARCHAR ('ENTRADA' o 'SALIDA').

concepto: VARCHAR (ej. 'OBSEQUIO', 'CONSUMO_INTERNO', 'EVENTOS').

tipo_inventario_afectado: VARCHAR ('ALMACEN' o 'MOVIL').

id_referencia_movil: UUID (NULLable. Obligatorio solo si el inventario afectado es 'MOVIL').

id_cliente: UUID o INT (NULLable, por defecto NULL. Se usa si el movimiento, como un obsequio, está vinculado a un cliente específico).

autorizado_por: UUID (Foreign Key a auth.users).

observaciones: TEXT.

2.2. Tabla Detalle: movimientos_inventario_detalle

id: UUID (Primary Key).

id_movimiento: UUID (Foreign Key a movimientos_inventario, ON DELETE CASCADE).

id_producto: UUID o INT (Foreign Key a la tabla de productos).

cantidad: NUMERIC/INT (Mayor a 0).

costo_unitario: NUMERIC (Costo del producto al momento del movimiento para auditoría).

3. LÓGICA TRANSACCIONAL (RPC PL/pgSQL)

Crea la función registrar_movimiento_inventario_especial que reciba los datos de la cabecera y un array JSONB con el detalle de los productos.

Inserción de Cabecera: Insertar el registro en movimientos_inventario y obtener el id generado.

Desglose de Detalle: Iterar sobre el JSONB de productos e insertarlos en movimientos_inventario_detalle.

Validación y Actualización de Stock:

Si es 'SALIDA', validar que exista stock suficiente en la tabla correspondiente (inventario_almacen o inventario_movil). Si no hay stock, disparar RAISE EXCEPTION para abortar la transacción.

Actualizar los saldos sumando o restando las cantidades.

Seguridad: Usar SECURITY DEFINER para asegurar la atomicidad de la transacción independiente de las políticas RLS del usuario operativo.
